# Reproducibility

What you need, besides this repository, to rebuild the mod from source, and what is still missing. It was put
together by reading the committed scripts (bootstrap, model build, full disc build, package engine and patch app);
it is not proof of a successful build from a fresh clone.

**In short:** besides your own game files, a few **helper scripts** are still missing from this snapshot. Don't try
a full build until those gaps are closed and your clean disc's hash matches.

The [expression inventory](../manifests/input-expression-inventory.json) lists where the source mentions file paths,
file reads and build commands. It errs on the side of listing too much (outputs and in-game file names are included).
The older [literal inventory](../manifests/literal-local-dependencies.json) is a supplement. Neither can follow
manifest rows, environment settings, glTF external files or missing helper imports; those are called out below.

All paths are relative to the repository root. "Local" means you supply it and Git ignores it. Use only copies you
are entitled to use; a hash or a selection record gives no permission to download or share a file. Don't fetch
missing files from other people's game dumps.

## Audio inputs

`spot33_sfx.py` is the authoritative slot-to-WAV list. All require **16-bit mono WAV**; the generator uses each WAV's sample rate. Required local paths under `kh2_export/sfx/`:

- `explosion/{start,orb,blast}.wav`;
- `firaga/{cast,flash,fly,explode}.wav`;
- `magic/{thunder_hit,ice_hit,thunder_cast,ice_cast}.wav`;
- `reflect/{se_177,se_139}.wav`;
- `keyblade/weapon-option-{A,B,C,D,E,F}.wav`, `guard-break-effect.wav`, `finishing-leap-{start,burst}.wav`, `aerial-finish-effect-{1,2,3,4}.wav`.

These are edited derivatives of user's acquired KH2 sounds. Source comments identify several native sound IDs and durations, but exact trimming, saturation/gain and selection-generation recipes are not consolidated in committed tools. Treat each as a missing provenance chain until documented, even if its filename is known.

## Engine/package and installer branches

`tools/dlc/pspenv.sh` needs `PSPDEV_HOST`, Docker and the local `dissidia-pspdev:1` image built from its Dockerfile. Engine and package commands need your own clean disc, a built PRX and package folders. The engine module's export list `tools/pkg/engine/extra/exports.exp` is missing from this snapshot. Schemas and owner tables are committed; game file contents and reference file lists are not. `run_host_test.py` reads a local disc even though it is a host test. Emulator launchers need copies of a profile and saves; the smoke checks need neither.

The patch app core and CLI need the Rust crates from `Cargo.lock` in your Cargo cache. The app window also needs the Tauri platform libraries and generated icons (`python3 tools/installer/app/src-tauri/icons/make_icons.py`). A real patch run needs a `release.json` and a matching patch, as described in [INSTALLER-TECH.md](INSTALLER-TECH.md); neither is included. The synthetic tests make their own files, so the smoke command needs **no game inputs**.

## What "reproducible" will take

1. Export the missing helper scripts (without personal data).
2. List every local map and manifest row and every external glTF file.
3. Give every selected intermediate file a repeatable recipe.
4. Pin the toolchain and encoder versions.
5. Keep generated outputs clearly apart from inputs.
6. Do a clean build from a fresh clone on the clean disc, and compare it with the release build file by file and in
   the game.

This page names the gaps; it doesn't pretend they are closed.
