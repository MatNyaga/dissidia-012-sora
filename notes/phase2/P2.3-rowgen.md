## In plain words (for Mat)
- Today Sora's table rows (his name number, his start equipment, his Labyrinth face, his place in the unlock list, …)
  are written by old one-off scripts at fixed "owner 33" addresses. The new tool **rowgen** writes them from his
  registry file and a table description instead. Every new fighter then gets its rows the same way.
- Proof: rowgen's rows for Sora are **byte-for-byte the same** as the frozen reference disc (18 tables IDENTICAL) and as
  the stored package rows. A test disc where rowgen wrote those rows is identical to the reference disc (even its
  checksum is the same).
- For the test fighter (owner 34) rowgen fills 10 tables and **refuses** the ones that are full, with the reason:
  Records icon, quick-battle grid, Characters panel list, EX Mode page, and the 5 name keys (the slot is free but
  the 6-letter key text needs a home first).

## 3. Design

**Input.** `registry.load_source` dicts (one per `--registry`, processed in owner order) + `owner_tables.json`
`rowgen` specs + the clean dump (read-only; the EBOOT is decrypted in memory with tools/scripts/eboot_plain.py, sha
checked). No package input: everything comes from the registry. The package is only used by `check --pkg`.

**Spec (`owner_tables.json` → `tables[].rowgen`, documented in `legend.rowgen`).** Per entry: `step` (D-id), and
either `parts` (data tables) or `kind: imm` + `sites` + `params`. Part fields:
- `kind`: `owner_row` (table[owner − index_base]), `key_ptr` (owner_row holding a key-string pointer),
  `list_row` (row at the registry slot: an int = reuse that vanilla row, `"append"` = at the terminator),
  `fixed_slots` (n slots for the packages that have `when_feature`), `grid_append` (container grid row).
- `image`, `base_va`, `stride`, `index_base`, `fmt` (Python struct), `fields` (registry paths `row.X` /
  `install.X`, `X.N` = list item, `X.*` = whole list, plain ints = constants), `max_owner`, `empty` (hex of a free
  slot in the clean image), `rows` / `terminator` + `end_va` (lists), `full` (why a new owner does not fit).
- imm sites: `image`, `va`, `clean` (expected clean word, a guard), `value` (a named rule in `rowgen.imm_values`, no
  eval): `ablt_cap`, `jb_*` (Jukebox shift), `assist_drop`, `card_cap`.

**Generation.** The clean images are copied; each package entry is written into the copy (refused when: owner past
`max_owner`, the slot is not `empty` and not already the same value, a reuse row taken twice, no room before
`end_va` for append, value does not fit the format, a registry field is missing). Then **img: rows are cut exactly
like `extract.py code_diffs`**: changed 4-byte words inside the table range, contiguous words merged, ordered by
image then VA, `note` = the code_sites.json range note (fallback `rowgen <id> (no code_sites.json range yet)`). That
is why the rows compare 1:1 with the package (e.g. Labyrinth row 33 starts at 0x08B41802, so the row is the word
0x08B41800 `55000000 → 55002d10`, owner 32's last field included, as stored).
Key pointers (D5): (1) the slot already points at the key string → unchanged; (2) else the first same-image key
table pointer that points at that string (spec order: menu A before C → C gets A's 0x089EA2F0, as R4 has); (3) else a
4-aligned copy of `key\0` in the image; (4) else refused (P2.3 Q8: the installer must give the string a home).
grwp: final row index = clean rows + earlier packages; row = (index, owner) + bytes 4..27 of the clean row of
`grwp_copy_owner`; row limit 64 (the RAM copy).

**check --disc** compares the disc's bytes over every table **range** (not only the package slots) with clean +
generated, and the container chunk with `containers.apply_grid(clean chunk, generated rows)`. **check --pkg**
compares the generated rows with the package's `rows/<id>.json` img:/grid rows (all fields incl. note) and the
generated edits with the package's `patches/<id>.json` edits at the generated VAs (other edits of those patches,
e.g. the other 121 edits of save_record_hooks.json and the 16 assistdup words of assist_drop_words.json, are counted as "kept").

**Test-disc writer `rowgen_disc.py`.** `strip` writes the clean bytes back at every rowgen site, `write` writes
rowgen's bytes. In-extent writes only: code-image words at their ISO file offset; main.bin re-encoded with
containers.py (delete / add the grwp row; canonical re-encode of the oracle's main.bin is byte-identical) and
written over its own PACKAGE.BIN extent (room = up to the next PACKAGE row, 1,222,656 B) + the PACKAGE_INFO size word
(tier bits kept). Guards: only `dumps/ULUS10566-P23-*.iso`; refuses the clean dump, the oracle, R3, R4-test, p18,
release discs and hard links to them (inode check); refuses a disc any process has open (/proc/*/fd); EBOOT must be
plain; no live EXTRA.IDX; every site must be in the before-state (after-state = skip) before the first write; grid
rows are tested for presence (an add has no old bytes: a second `write` would otherwise add a duplicate row — found in
a dry re-run and fixed before the final cycle); read-back after fsync. `--dry` writes nothing.

## 5. Registry fields added (P2.3 Q9)

`install.*` (all `[value, source]`; `_rowgen` = a comment string; registry.py V12 checks types, flags in the
package's own list, unique int slots / icon ids; missing fields = warning, rowgen then refuses those tables):
`manikin_name`, `start_preset`, `labyrinth_icon`, `records_icon`, `unlock_row`, `unlock_flag`, `costume_flags`,
`seen_flag`, `qb_row`, `qb_logo`, `char_number`, `select_panel_pos`, `ex_page_row`, `ex_page_texts`,
`grwp_copy_owner`, `ablt_rows`, `jukebox_group`. Sora's values are the R4 bytes (sources: the spot33 scripts named in
each field). test34's are placeholders (owner-33 pattern + 1, `"append"` slots). They are install-time values, so
EXTRA.REG is unchanged. `pic_slot_party` stays redundant (= pic_slot + 1, V5).

## 7. What install.py needs later (not edited: the EXRUN pilot helper owns tools/pkg/install*.py)
1. Know the installed roster: the registry sources of every package (proposal: `manifest.registry` = path of the
   package's registry source inside the package, or a roster file passed to the installer).
2. Before `pkgapply.contents()`: `g = rowgen.generate(registries, DiscImages(clean))`; stop on `g.refusals()` for
   any table the package needs (message = the refusal text).
3. Replace, per package, the stored rows of the 18 covered ids: drop `ns img:*` rows of those tables and the grwp
   grid row, add `g.tables[id]['rows'] + ['pkg_rows']` once (they are roster-wide: build them for all packages
   together, never per package — two packages would otherwise both claim "row 32" of grwp or the same unlock end).
   Keep the package's other rows in those tables (the GIM asset rows of labyrinth_face / records_icons).
4. Replace the patch edits at the imm sites (ablt_cap, jukebox_list_code 10 words, assist_drop_words 3 words,
   save_record_hooks 2 cap words) with `g.tables[id]['edits']`; keep the other edits of those patch files.
5. code_sites.json ranges cover only owner 33's words today (e.g. scenario_names 0x089CF3D4..D8). A disc with owner
   34 rows would show "no code_sites.json range" in extract/equiv → widen the ranges to the full table ranges
   (`rowgen.py` regions) when owner 34 lands (equiv `--allow-site` uses them too).
6. Layout B: the img: rows and imm words are code-image writes (same as today); grwp is a PACKAGE row → EXTRA.IDX
   path as today. rowgen_disc.py is layout R/A only; the installer keeps its own placement.
