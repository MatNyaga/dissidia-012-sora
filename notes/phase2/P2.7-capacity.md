## In plain words (for Mat)
- **The character grid now has room for a 34th fighter.** The grid's list of rows was full and something else sat
  right behind it, so a second fighter could never be picked. The list now lives in a free piece of the game's main
  program, written by the installer from the fighter files. The grid code was told where the new list is (2 words) and
  got a small safety check for the two screens that add an extra "empty" cell (with 33 fighters they would need a
  35th cell, which does not exist). With only Sora installed the grid looks and works exactly as before.
- **One tool now writes every "installer number" from the fighter files**: the unlock list row, the Opponent Info
  name row, the name keys (with a fixed home for a new fighter's 6-letter key), the ability-table limit, the icon
  buffer size, the Jukebox list sizes, the grid bounds, the friend-card limit, the title-call tables and the
  per-fighter tables of P2.3 / P2.5. With only Sora every one of those numbers is exactly what the P2.5 disc has.
- **Title calls for new fighters: possible with no new game code.** The same layout trick the release used for Sora
  works for one more fighter (36 callers). The real limit is the calendar: only days 26 and 31 are still "spare"
  (§4, question for you).
- The checker for fighter files (registry) now refuses owner numbers above 34 and checks the new title-call and
  grid fields. The item-number limit (683) now has one source for the module and the checker.
- For every capacity item of the research list there is now a decision (§3): done now, accepted as a known limit
  for the test fighter (you said that is fine), or needed before a real second fighter (with the cost).

## 2. The generic writer (`p27_words.py`) — what it writes, from where
`p27_words.py DISC --registry NAME ... [--from NAME ...] [--dry] [--rollback]`, `--plan` (no disc). Inputs: the
registry sources and owner_tables.json only (no owner number, key or fighter name in the tool). Three generators:
1. **rowgen** (every table row and installer immediate of the 3 code images): D1 scenario names, D2 start preset,
   D3 Labyrinth face, D4 Records icon (unread since P2.3), D5 the 5 name-key tables + **D5b KEY_POOL** (a key that
   has no resident string in every key-table image gets an 8-B slot of the EBOOT KEY_POOL 0x089A8D7C; the tables
   point there — EBOOT is mapped under every overlay), D6 Opponent Info row, D7 OQ tables, D8 unlock row, **D9 grid
   rows (GRD1 block)**, **D9b grid bounds**, D10 select panel, D11 EX page, **D13 title call**, D14 ablt cap /
   **uicn buffer** / Jukebox shift / assist drop / friend-card caps. (D12 grwp = a container row: reported, written
   by the installer's container step.)
2. **OXT** roster columns (`p23_lookups.tables(roster)`; the roster-independent part stays p23_lookups').
3. **SRC1** REC_CAP / REC_MARK / REC_FLAGS (`p25_saves.record_data(roster)`).
Guard: each region must hold the target, an accepted roster's bytes (sora + `--from`) or the clean bytes before
anything is written; refusals of the known-limit tables (records_icons, select_panel_list, ex_mode_page) are listed,
any other refusal stops the write; read-back after fsync.
**Sora-only = the P2.5 disc in every word except the new GRD1 block** (host test A1: 41 items). The writer replaces,
for the installer (P2.8 step E3), "rowgen + p23_lookups tables + p25 record data + the title_call patch".

## 4. Title call (#17) — design, built as a generator
Static analysis (sub-helper scripts in the session scratchpad `p27/tc/`). FUN_089deaa8 plays
`voice/JP/event/title_call/<SQE name>.at3` + `<DDD name>.at3`; the caller index comes from FUN_089dfd6c: a day table
(31 u32 at 0x089E07D8) plus fixed vanilla overrides by caller key (gi on day 15 once Gilgamesh is unlocked, pr, gs,
ae, na on dates / times, co on the save's weekday, ch 5 % random once Feral Chaos is unlocked, na last). The only bound is the caller-count immediate N at 0x089DEC04. The caller index is not
the owner (series order; vanilla 0..33 are fixed by the override immediates). Day callers have no unlock gate.
- **Generator (rowgen kind `title_call`, D13):** N = 34 + packages with `install.title_call {sqe, ddd, days}`; index
  = 34 + position (owner order). DDD table N words at 0x089E0504 (base word 0x089DECD0), vanilla DDD strings +
  package strings packed first-fit up to 0x089E06F1 (live data after it) and after the SQE table up to 0x089E09C0
  (live global), rest 0; bound = N; day table entries = the index. **Sora-only = R4's 155 title_call words exactly**
  (check --pkg sora-R4 IDENTICAL 155 edits; check --disc P25 IDENTICAL) → the `title_call` transitional patch can
  retire (P2.8 E5). Sora + test34 (placeholder: Cloud's files, day 26) = 36 callers, bound 36, strings fit
  with 11 + 24 B left. No package = the clean bytes.
- **Capacity:** 36 callers (= Sora + one more) with `title_xx_SQE / _DDD` names. More: repack the SQE strings too
  (39, 0 new words) or one key per caller (68, 2 extra code words) — later.
- **Days are the real limit:** vanilla callers with two days: Garland 21/31, Exdeath 15/25, Kefka 16/26, Kuja 19/29;
  R4 took 25 and 29. Free second days left: **26, 31**. Side finding: on day 15 the Gilgamesh override (once he is
  unlocked) beats Exdeath, so on R4 Exdeath never gives the title call once Gilgamesh is unlocked.
- Registry V13: stems `title_<xx>_SQE/DDD`, days unique 1..31 across packages, a day outside 26/31 = warning (Mat
  decides), `install.title_call_index` = informational (derived per roster).
