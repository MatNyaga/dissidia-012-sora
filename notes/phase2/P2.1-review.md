# P2.1 design review — docs/ENGINE.md "Registry + stubs v2 (DRAFT, P2.1)"

Review 2026-10-20 by Claude (P2.9/P2.10 research helper), static, against: the P2.0 owner-33 inventory v2 (86
places, byte-checked, notes/dlc-phase2.md), the P2.9 owner-34 recipe (notes/phase2/P2.9-testfighter.md), the clean
decompile (dumps/decomp/all.c) and Phase-1 lessons (notes/dlc.md §F). PHASE2-PLAN P2.1 asks for a review by "the
other agent"; Codex was asked on 2026-10-19 and has not answered in codex/QUESTIONS.md, so this is a Claude review —
a Codex review is still welcome.

## Verdict
The core choice is right and should stay: **fixed EBOOT stubs that jump through data pointers** (module writes data,
never instructions), EBOOT-resident O(1) lookup helpers, install-time data for everything that is "just a table row",
a loose `EXTRA.REG`, append-only status block. Nothing here forces a redesign. But the draft is **not yet safe to
freeze**: 4 issues would bite owner 34 or a real-hardware run, and the REG block has no room for P2.7's relocated
buffers. Fix list in §2, ordered by severity.

## 1. What is good (keep)
- Data-indirect stubs (`lui at / lw at,FN_PTR / jr at / nop`): no instruction writes → the P0.7 JIT problem cannot
  come back; a stub compiled before module_start still sees the new pointer (real load each call). On hardware no
  cache maintenance is needed (cached `sw`, cached `lw` on the same CPU).
- Overlay re-read handled correctly for code: overlay hook words are disc patches that hold only **stub addresses**
  (fixed, EBOOT, same 256 MB `jal` segment), never module addresses.
- `$at`-only clobber contract, checked on all hook delay slots; registry builder enforces it.
- Validation-before-publish load rules for EXTRA.REG, `REG_PTR` = 0 on any failure, status codes.
- Dense owner − 33 row array (1,984 B) → every helper O(1); loops only in list builders (P2.0 per-frame rules).
- Freed-range proof (static re-scan + runtime marker probe test272p).

## 2. Issues and concrete fixes
### 2.1 [HIGH] "Vanilla-safe" covers vanilla fighters only — package fighters stay visible when the engine is not live
ENGINE §6: "a disc with packages but no usable registry runs package fighters in a degraded way (vanilla paths for
owner ≥ 33)". In practice the unlock table rows, grid rows, select list, Museum rows etc. are install-time data, so
the fighters still **appear**; picking one then reads the vanilla tables at owner 33/34 (e.g. name index table
0x089CC020[33] = 795699042 = string bytes on the oracle, `owner_names.py`) and, in layout B/C, finds **no files**
(EXTRA.IDX is served by the module). That is the F-10 pattern (PPSSPP shrugs, hardware crashes). Causes we cannot
rule out on a player's console: module load failure (plugin conflict, memory), corrupted EXTRA.REG, old EXTRA.REG
after an uninstall (see 2.4).
**Fix:** make visibility a registry lookup, not install-time data: hook the unlock walker (EBOOT FUN_088d5ac8 /
FUN_088d5ce8: the source of the select grids' "available" list (P0.5 builder FUN_08a84fd4) and, per the decompile, read at 18 menu-overlay sites — confirm in P2.3 that every picker and Museum list goes through it) so that an owner ≥ 33 is
listed only if `REG_ROW(owner) != 0` (one L site, ~6 words, list-build only = not per frame). With the module or
registry missing, the game is then exactly vanilla + inert data. Add it to the inventory as a generic site (it has
no owner constant). Optional belt-and-braces: install-time "safe" values in the vanilla tables for package owners
(e.g. name index = the fighter's own entry, not junk), so a missed lookup site shows a wrong name, not garbage.

### 2.2 [HIGH] Feature-gated stub install leaves owner 34 with Garland's equipment (mask alias)
Stubs are written only "for each stub n the module implements and whose feature is used by at least one loaded
row". The equip/unlock/AI masks use bit (owner − 1) & 31 → owner 33 aliases WoL (bit 0, fixed today by the item
code), **owner 34 aliases Garland (bit 1)**. A package without own items (test34: features PKG_FLAGS + RECORD_SLOT)
never switches on ITEM_ELIG / ITEM_ROWMASK / ITEM_MENU, so Test Fighter sees Garland-only gear and Garland's lists
may treat Test Fighter's rows as his.
**Fix:** the item-eligibility stubs (S15-S17, + S20 shield) are installed whenever **any row has owner ≥ 33**
(alias is a property of the owner number). Wrapper rule: for a package owner, a vanilla item is eligible iff its
owner mask is "all fighters"; single-fighter vanilla items are never eligible; package items via ITEM_OWNER. Same
question for the AI auto-equip mask (`acit`, P0.4 row "unlock / equip / AI-item masks") → P2.4 must list its reader.
Registry: a derived feature bit `OWNER_MASK_FIX` set by the builder for every row (no source field needed).

### 2.3 [HIGH] Stub table placement vs. transition order
The stub table, REG block and fallbacks live in the **TRI** range 0x089C1C9C–0x089C2508, which holds TRI (536
words) + EE_HIT/EE_GUARD until P2.4 has ported them; the helpers live in the EXRUN/EXITEMS range, which holds
EXRUN/EXITEMS/EE_B and PANEL_LIT's target 0x089A8DC4 (menu overlay `jal`, inventory #13). So no stub can be
installed and no helper can be placed until the corresponding ranges are **completely** emptied. P2.3 (lookups)
needs the helpers, i.e. needs EXITEMS + EXRUN + EE_B moved first (P2.4), contrary to the plan's "P2.3 and P2.4 in
parallel".
**Fix (choose one, write it into ENGINE.md):** (a) P2.4 order = EXRUN → EXITEMS (incl. the PANEL_LIT target) → EE_B
→ then the helper range is free for P2.3; TRI last, then XSTB. (b) Put the 5 lookup helpers (~63 words) in the
52-word SCALE range + 11 words elsewhere — no, too small; or (c) temporarily put helpers **in the module** reached
through stubs — defeats "lookups without the module". → Recommend (a) and state it as a dependency in PHASE2-PLAN.

### 2.4 [MEDIUM] Versioning: three files, no common identity
XSTB (on-disc EBOOT patch), EXTRA.PRX (module), EXTRA.IDX + EXTRA.REG (installer output) are versioned separately
(XSTB version/count, REG version + min_engine_version, status layout). Missing:
- **Stub ABI identity.** Index n means "this site, this register contract, this fallback". If a later engine patch
  moves or re-orders a stub, an older/newer module installs wrappers with the wrong contract — silent corruption.
  Fix: XSTB header `u32 abi_hash` = hash over (n, name, site VA, contract) of the stub list; the module embeds the
  same list and refuses (stub_state −4) on mismatch. Costs 1 word (take it from the 270 spare words).
- **Roster identity.** Nothing ties EXTRA.REG to the installed packages or to EXTRA.IDX. A stale EXTRA.REG (package
  removed, files gone) passes every check. Fix: both headers carry `u32 roster_id` (hash of sorted package ids +
  package_sha256), installer writes the same value into both; module: mismatch → reg_state −9, nothing published;
  each row gets `u32 package_sha_prefix` (use reserved 0x27 + params? no — grow the row; see next point).
- **Row growth.** "File rows may be longer, readers use the first 64 B" is good; add `u16 minor` to the header so a
  v1.1 reader knows which extra fields exist (today `version` u16 only).
- Checksum: 32-bit sum misses swapped words; CRC-32 costs ~0.3 KB in the module. Minor.

### 2.5 [MEDIUM] REG block too small for P2.7: module-owned buffers must be reachable from overlay code
P2.7 relocations (Records array 32 × 0x10C, Jukebox character list + voice-row buffers, grid row table 408 B, select
list, OQ face handles, Museum viewer list) need overlay code to find a buffer **after every overlay re-read**. A
module address cannot be patched into an overlay (re-read from disc), and the module has no "overlay loaded" hook.
The REG block has 8 reserved bytes.
**Fix:** define now a fixed pointer table in the REG block, e.g. `BUF_PTR[8]` + `u16 buf_size[8]` (0x30 B), each
defaulting to the **vanilla** buffer address on disc (so overlay code that reads `lw t, BUF_PTR[k]` works without the
module), replaced by module_start when it allocates the bigger buffer. Overlay sites then read the pointer from the
fixed EBOOT address (data-indirect, same as the stubs). Alternatively install-time buffers in EBOOT free space if
small enough — but the freed ranges are already planned for stubs/helpers.

### 2.6 [MEDIUM] Publish order and wrapper preconditions
module_start writes FN_PTRs, then publishes REG/FLAG/ITEM pointers ("REG_PTR written last"). Between the two, a
wrapper can run (other game threads exist at boot: sound, file I/O) with REG_PTR = 0.
**Fix:** publish REG/FLAG/ITEM/BUF first (rows complete), FN_PTRs last; and every wrapper starts with
"REG_PTR != 0 and owner is a package owner, else jump vanilla[n]" in asm before any C prologue (also the cheap path
for vanilla fighters on per-frame stubs: EXRUN every fighter every frame, HELM every fighter in EX).

### 2.7 [MEDIUM] Wrappers must not assume which overlay is resident
Menu and battle overlays share the base 0x089DD4C0 (F-11). EBOOT hooks C1 0x0880A384, C2 0x0880A408, C4 0x08808B74
jump into the battle-overlay cave today (valid only because they fire in battle); ITEM_* hooks are EBOOT functions
called from both menu and battle. Through the stubs they reach the module from any context.
**Fix (ABI rule):** a wrapper may read overlay data only after checking which overlay is loaded (a global the game
keeps, or the first words at 0x089DD4C0 vs. a known signature); wrappers called from EBOOT sites use only EBOOT /
module data. Add a host test (P2.4) that calls each wrapper's "wrong overlay" path.

### 2.8 [MEDIUM] Fallback correctness rule
Fallbacks are "displaced original instruction(s) + `j` back". A displaced word that is PC-relative (b*, bal) or a
`j/jal` with segment assumptions changes meaning when moved; C1 0x0880A384 is a mid-function `j`.
**Fix:** registry/engine builder check "displaced words contain no PC-relative branch and no delay-slot dependency",
and a host test that runs each fallback in a MIPS emulator (or at least disassembles and compares) against the clean
function. The module must never verify instruction words of code that may be JIT-compiled (PPSSPP puts emuhack
markers at block starts, P0.7); verify only data words (magic, FN_PTR range) — already the case, keep it explicit.

### 2.9 [LOW-MEDIUM] Gaps vs the inventory v2 / owner 34
- **S23 EX_SND: drop it.** Never built (TRINITY_CTL = 1, inventory v2 #12). Stub list = 23 used (0-22), 9 spare; keep
  feature id 3 reserved ("retired"), never reuse the number.
- §4 "Not in the row" list misses: `opp_info_name` (battle 0x08AFB6E8, rows end at owner 34; P2.0 found it is the
  same table as `battle_names_file`), `grwp` row (mandatory, F-10), select blurb entries, `menu_clock` (engine base,
  not a package item), Cosmos fix F6 (engine-base data whenever owner 34 is used), the visibility gate of 2.1.
- **Name-key strings for a NEW key.** Sora reused Aerith's existing `sev120` strings. A new key needs a string for
  the EBOOT pointer table 0x089D6CA8[owner] (EBOOT is resident: module may write a pointer to its own string at boot,
  but then the key is missing without the module — acceptable with 2.1), the menu table 0x08B57FBC and the battle
  table 0x08AFBC68 (both in overlays → pointer must target fixed memory: install-time strings in overlay or EBOOT
  free space, or a lookup site). Registry `key_off` (module string table) cannot serve overlay tables. → P2.7 item.
- **Owner ceiling.** Registry allows 33..63 (warn > 35), but chrp rows, Opponent Info rows, grid bounds and the stats
  "vs" block end at **34**. Make the validator ERROR for owner > 34 until P2.7 relocates them.
- **Flag bitmap = one range** [FLAG_LO, FLAG_LO + FLAG_BITS). Sora's gate flags 888..1270 + package #2 in 3200-3455
  → span 888..3207 = 2,320 bits (290 B): fits, but grows with every pool. Use a short list of (lo, bits, off) ranges
  in EXTRA.REG; REG_FLAG loops ≤ 4 ranges (list builders only).
- **objentry companion lookup** (Cosmos, P2.9 §3): not an owner-33 constant, so no inventory site; the engine must
  either apply F6 (data) or convert FUN_08843710 / FUN_08843854 / FUN_08845230 (generic code, F2). Add to the plan.
- Assist: the row has no "has assist" bit; pickers (inventory #4, Aerith append) need to skip package owners without
  an assist.bin row. Add feat bit `HAS_ASSIST` (builder sets it from the package rows) or make the REG_NEXT loop check
  the assist.bin row.
- `burst_ctl` ∈ {0xFF, 0x80}: fine for test34 (0xFF = chrp choice, no module).

### 2.10 [LOW] Per-frame cost — fine, with two rules
Numbers from the inventory v2: menus run 233-369 k ticks per frame of a 7.4 M budget (222 MHz); a REG_ROW lookup is
~15 instructions + `jal`; 100 calls per frame < 0.1 %. Stub path per call: 4 + wrapper owner test (~6) + `jr` back
to the vanilla function. On PPSSPP a `jr at` to a computed target costs a dispatcher lookup (no block linking) —
per-fighter-per-frame calls (EXRUN, HELM) stay far below 1 %. Rules to write into ENGINE.md: (1) owner test in asm
before any C prologue (2.6); (2) no REG_NEXT / REG_BY_MUSEUM / item searches in draw paths (P2.0 per-frame list).
The Vita menu lag was the CPU clock (fixed by menu_clock), not hook cost; B15 (frames.py vs oracle) stays the gate.

### 2.11 [LOW] Smaller points
- EXTRA.REG as a loose file next to EXTRA.IDX: fine on PPSSPP, Vita (disc0: through Adrenaline) and after Data
  Install (the module reads disc0:). State in ENGINE.md that the module opens it with the same path rules as
  EXTRA.IDX and that layout A discs (no module) never get packages with the engine.
- `REG_ROW` returns 0 also for "row exists but invalid": keep, but count rejects in status (first_bad).
- status 0x90 stub_state: add −4 "abi_hash mismatch" (2.4); reg_state −9 "roster mismatch".
- `params[16]` + `aux` is fine; give `aux` a TLV header (u16 type, u16 len) so P2.4 behaviours can add tables
  without a format bump.

## 3. Does anything block owner 34?
Blocking in the ABI as written: **2.1** (safety on hardware), **2.2** (Garland gear), **2.5** (no way to reach the
relocated Records/Jukebox/grid buffers from overlays), name-key strings (2.9), Cosmos companion lookup (2.9), owner
ceiling check (2.9). Not blocking: stubs, helpers, row layout (all owner-34 fields exist; test34.json fills them),
per-frame cost. Plus one non-ABI blocker found in P2.9: the package format cannot merge two packages' edits of
bytes-leaf tables (acab/amas/chrl/brai/texts) — notes/phase2/P2.9-testfighter.md §5.
