## In plain words (for Mat)
- **The engine is now a package of its own** (`packages/engine`), made from the clean game, like a fighter. It holds
  the engine program (EXTRA.PRX), the list of game-code changes every roster needs, and the menu-speed fix.
- **Sora is now package #1 on that engine** (`packages/sora-C`, a new folder; the old ones are untouched). It no
  longer carries any game-code patches: everything it needed is either engine code now, or numbers the installer
  computes from Sora's registry file. Its edits inside shared game files are stored by "what they are" (owner,
  text entry, id, picture number), so a second fighter can be added next to it later.
- **A new install mode "C"** builds a disc from your clean ISO + the engine + any fighters. The old modes A and B (the
  released 1.0 path) are unchanged, checked by comparing the old and new installer on Sora's package.

## 2. E2 — format 1.1 codecs + packages/sora-C
**Codecs** in `tools/pkg/containers.py` (additive; a row without `codec` behaves exactly as before): odir.v1, acab.v1,
text.v1, grid-id.v1 (ablt, objentry, **eqpm** — eqpm turned out to be id-sorted, Sora's preset 250 is inserted at row
34), positional.v1 (one contiguous block; **collection_param sec8** inserts Sora's row at 32 = owner − 1 before the last
clean row, so "append at the end" was not enough), append.v1 ("owner:k"), pak-fill.v1, bytes.v1. Spec:
docs/PACKAGE-FORMAT.md §16.1. Design change vs P2.8 §3: the codec sits on each ROW and the identity is in `key.at`
(key_fields stay ["at"]), because one owner_tables table can span two node kinds (museum_icons).
**Validator** (`tools/pkg/validate.py`, `pkgformat.FORMAT_MINOR` = 1, schemas extended additively): 1.1 rules —
registry.json (owner / package = manifest), layout C needs the engine, known codec per row, `key.at` type per codec,
text.v1 replace/delete need old_sha256, no final-index grid adds, byte-offset rows must be bytes.v1; across packages a
bytes.v1 ns edited twice = error, a layout pin on a container another package edits = warning (canonical re-encode).
1.0 packages: outputs byte-identical (sora-R4, sora, sora-R2, examples/mini, the sora-R4 + mini pair).
**Converter** `tools/pkg/pkg11.py convert packages/sora-R4 packages/sora-C --registry tools/dlc/registry/sora.json`
(sora-R4 is only read; OUT must not exist). It re-keys every row, drops the 17 `img:` rows and the grwp row (generated;
the grwp row is checked = rowgen's) and the 1,356 picture-pack fillers (derived), carries no code patch, copies the
files (minus the eboot produce entry), writes registry.json (canonical copy of the registry source) and **proves before
writing** that every PACKAGE file the rows touch (70) comes out byte-identical from the clean bytes with the 1.0 rows
and with the 1.1 rows (+ generated rows).

**Result** `packages/sora-C` (format 1.1, layouts [C], requires engine >=2.5.0, registry.json, features {}, patches
none), package_sha256 **c89e2305…256b**, 34 MB like sora-R4: rows text.v1 494, append.v1 60, pak-fill.v1 44, grid-id.v1
36, positional.v1 21, odir.v1 2, acab.v1 1 (Sora shares owner 13's AI list), bytes.v1 155 (brai seco 15, battle voice

## 4. Decisions (made here, with the reason)
- **Engine base = the P27 engine disc minus the clean dump, minus loader / menu_clock / generator regions.** Generator
  regions (rowgen tables, GRD1, OXT tables, SRC1 data, panel_tex) are always written by the installer for the roster
  (also the empty roster), so the base never stores roster data; the installer refuses a package patch that writes
  inside a generator region.
- **Codec on each row, identity in `key.at`** (instead of per-file key_fields): one owner_tables table can span two node
  kinds; keeps the validator's (table, ns, key) clash rule meaningful (two packages adding owner 34 twice clash, 33 vs
  34 do not).
- **Text rows ship plain text and only a sha256 guard of the clean entry** (`old_sha256`), so a 1.1 package ships no
  clean game text at all (1.0 shipped XOR-ed clean bytes as old_raw).
- **Tables without an identity codec yet stay byte-offset rows, sole editor (`bytes.v1`)**: brai seco, the string
  tables (ability / item / item_help / bgm_name / battle_voice_name), manual / command_list / update_list params,
  assist. Sora-only discs are exact; a second package editing the same node is refused by the validator. Building
  identity codecs for them is P2.9 / E8 work (it needs the file formats; scripts listed in P2.8 §3.3).
- **positional.v1 = one contiguous block** that may start before the clean end (collection_param sec8). A gap (a
  package owning lower positions is missing) is refused, not filled: the "inert filler row" question (P2.8 §3.3) stays
  open and only matters once two packages exist and one is removed.
- **Layout C placement = layout B**, plus: an engine-only disc gets no EXTRA.IDX and keeps the PACKAGE.BIN record.
- **Q-P28-M1 (menu_clock for every roster) = yes** (Mat, 2026-10-22): the engine package carries `menu_clock.json`;
  switch: `make_engine_pkg.py --replace --no-menu-clock`. **Q-P28-M2 (canonical re-pack with two fighters) = yes**
  (Mat): `install.py --layout C` drops a pin when two packages edit its container (reported in the summary
  `pins_canonical`); switch: `--pins refuse`. Sora-only discs are unaffected (proven byte-identical above).
- `make_engine_pkg.py` uses the Sora roster (tools/dlc/registry/sora.json) only to check that the engine disc it reads
  is a Sora-roster disc; nothing of Sora goes into the engine package.
