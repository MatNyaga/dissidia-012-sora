# P2.10 — test kit: inventory of the PPSSPP session tools + plan for `tools/qa/runtime/`

Written 2026-10-20 by Claude (P2.9/P2.10 research helper). Research + one preservation copy; no emulator run.
Acceptance list that uses these tools: docs/PACKAGE-ACCEPTANCE.md (DRAFT, extended today).

## In plain words (for Mat)
- Over the last weeks we wrote about **125 little helper scripts** that drive or read the emulator: about 37 are in
  the project folder, the rest (about 90) only in a temporary session folder that disappears with the session.
  Most of the useful "session tools" from Phase 1 (music pick logger, unlock-flag dump, menu speed counter,
  Opponent Info trace, teleport + gauge-fill lab) were **only** in that temporary folder.
- I copied the 29 important ones **unchanged** into `tools/qa/runtime/snapshot-20261020/` (with checksums) so they
  are not lost. They still assume Sora (owner 33) and fixed addresses.
- Plan: one small shared library + one command (`tools/qa/runtime/qart.py`) that takes the fighter package name,
  reads the fighter's number, flags and names from the registry and the game addresses from one address file that
  is checked against the oracle disc before every run. Then every acceptance item can be run for Sora, the test
  fighter or a future fighter with the same commands.

## 1. How the tools talk to PPSSPP
- Debugger WebSocket on the RemoteISO web server: `ws://127.0.0.1:<port>/debugger`, Python `websocket` with
  `suppress_origin=True`. Mat's profile has `RemoteISOPort = 41335`; every isolated launcher rewrites it to **41336**
  → 41336 = disposable profile, 41335 = Mat's own (never for tests).
- API methods used: memory.read / write / disasm, memory.breakpoint.add / remove; cpu.breakpoint.add (enabled, log,
  logFormat) / remove / update / list, cpu.stepping (command + event), cpu.resume, cpu.runUntil, cpu.getAllRegs,
  cpu.getReg, cpu.status; input.buttons.press / send, input.analog.send; gpu.buffer.screenshot (fails on this setup →
  ImageMagick `import -window` instead), gpu.record.dump; hle.func.list, hle.thread.list; game.status.
- Rules learned: one WebSocket client at a time; a leftover breakpoint freezes the game (docs/learn/09-testing.md);
  log-only breakpoints = `enabled=False, log=True` (output in ppsspp.log); sceIo stub breakpoints do not fire under
  the JIT (iocount/ionav); window-only screenshots (`xwininfo -root -tree | grep -i duodecim` + `import -window`).
- No shared package today: de-facto libraries `tools/scripts/ppdbg.py` (call, read) and `tools/scripts/ppplay.py`
  (VT, call, read, find_fighter); every other script repeats its own `call`/`rd`/`wr`.

### 2.5 Procedures without a script
- **OQ Test → pause → Win:** the game's own Original Quest editor Test mode; its pause menu has Win/Lose. Driven by
  hand or pp.sh presses (notes/dlc-phase1.md RR-18). No script.
- **Unlock flag maths:** flag word = *(u32)0x089D726C + (flag >> 5)·4, bit 1 << (flag & 31). 925 = +0x70 bit
  0x20000000, 888 = +0x6C bit 0x01000000, 1263-1267 = +0x9C bits 15-19, 1372 = +0xA8 bit 0x10000000. PP was poked
  at 0x096B2DC0 by hand.
- **Fighter:** vtable 0x08B3A9A8 at F+0x544; side-0 fighter = *(u32)(*(u32)0x089D6A10 + 0x38); position F+0x80,
  facing F+0x90, EX gauge *(F+0x52C)+0x18 (0..10000), assist gauge +0x1C, bravery +0x14, HP +0xC − +8, EX flag
  F+0x5B2 & 4.
- **Opponent Info (2026-10-20):** breakpoint on the text call FUN_0887B3EC with PRESS=cross → `ra=08af9124 a1=1
  a3=0x32` (Lightning 50); row poked with memw 0x08AFB7F0 = 3f000000 3f000000 → a3 = 0x3F; table 0x08AFB6E8 +
  8·owner + 4·variant; 2nd reader 0x08AF9DB0.

## 3. Fold plan — `tools/qa/runtime/`
### 3.1 Layout
```
tools/qa/runtime/
  qart.py            one entry point: python3 -I tools/qa/runtime/qart.py <command> [--package ID] [--port 41336]
  ppws.py            the only WebSocket client: connect (refuses 41335 unless --own-profile), call/read/write,
                     breakpoint context manager (always removed on exit / Ctrl-C / SIGTERM), log-only bp helper
  addresses.json     every runtime address + the oracle bytes that prove it (see 3.2)
  pkgctx.py          package → owner, key, name_index, flags, items, costumes: from tools/dlc/registry/<id>.json
                     (and later EXTRA.REG decode); no default owner
  screens.py         window id lookup + game-window screenshot + thumbnail compare (go_battle refs)
  seq/               press sequences as data (oq_test_win.seq, qb_setup_minimal_os.seq, data_install.seq)
  snapshot-20261020/ unchanged session copies (kept today), deleted once their command exists
```
### 3.2 Addresses from data, checked before use
- `addresses.json` rows: `{name, va, kind: code|data|ram-ptr|struct-offset, expect_bytes (code/data only), verified_on:
  oracle sha, source note}`. Code/data addresses (VT, BGM pick 0x0888B544, fallback 0x0888B660/0x0888B6AC, file lookup
  0x088713E4, objentry lookup 0x08846CCC, Opponent Info text call 0x0887B3EC + table 0x08AFB6E8, vblank stubs
  0x089C5AC8/AD0, scePower 0x089C5800, win scene 0x08B0A090, sound play 0x08991A70, flag ptr 0x089D726C, save base
  0x089D712C, grwp ptr 0x089D73FC, side-0 table 0x089D6A10) are taken from `tools/dlc/owner_tables.json`
  `address_conventions` + the decompile notes. Fighter struct offsets (+0x80, +0x90, +0x52C→+0x18/+0x1C, +0x544,
  +0x5B2) as `struct-offset`.
- `qart.py selfcheck DISC` (static, no emulator): reads every `expect_bytes` from DISC through the same ISO readers as
  owner34_scan.py (EBOOT sector 560 / overlays) → refuses to run commands whose address moved. `qart.py selfcheck
  --live` does the same through memory.read on the running game (catches the overlay that is loaded right now:
  menu and battle share base 0x089DD4C0, F-11).
- Package-dependent values come only from `pkgctx`: owner (finder), flags (flag dump), name index (Opponent Info
  expectation), costume count (viewer check), BGM ids, record slot (save check). For engine v2 discs, `pkgctx --live`
  decodes the registry rows from RAM via the status block (REG_PTR) — the same bytes the game uses.

### 3.4 Steps (owner: whoever claims P2.10 tools; Claude canonical rule applies to tools/scripts only)
1. ppws.py + addresses.json + `selfcheck` (static first; test on ORACLE and CLEAN: every code address matches on both
   except the ones the oracle patches, which must be marked `oracle_only`).
2. pkgctx.py on `sora.json` and `test34.json` (+ EXTRA.REG decode via registry.py).
3. Port in this order (each = one acceptance item): status (B0), names (B16, B9 support), flags (B2), bgm (B9),
   oppinfo (B4), frames/clock (B15), find/tele/fill/hp/win (B5/B6/B7), record (B12), seq files (E6, B10).
4. Dry run: R4 strict smoke (section E) with `--package sora` must reproduce the R4/RC3 results (Opponent Info
   "Lv37 Sora", 333 MHz, Data Install COMPLETE, OQ slot face + name, 0 bad accesses). Plan text says "against p17
   reproduces RC2"; p17 is superseded by the oracle R4.
5. Retire: go_battle.sh / drive_qb.sh (normal profile, blind), pp_guard_snd.py + exprobe/guard_snd (port 41335), then
   delete `snapshot-20261020/` entries as their command lands.
### 3.5 Safety built in
- Refuse port 41335; refuse to run if two PPSSPPSDL processes exist and no PID is given; never `pkill`.
- Every breakpoint inside a `with` block; on exit list breakpoints and remove leftovers (`cpu.breakpoint.list`).
- RAM writes (`hp`, `fill`, `ramrow`, `--force-opponent`) print what they changed; acceptance records mark any
  result obtained with a RAM write as "assisted".
- Screenshots: game window only, into `dumps/screens/<disc-sha8>/`.
