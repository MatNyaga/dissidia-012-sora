Written 2026-10-20 by Claude (P2.3 names helper). Plan: [docs/PHASE2-START.md](../../docs/PHASE2-START.md) §5.3,

## In plain words (for Mat)
- Two small game functions answer "what is fighter N called?". Until now each had a special line "if it is Sora,
  say name 63". Now both read the fighter's name from one table row that the installer writes for every fighter
  (the same row the Labyrinth already used). No special case for Sora is left in them.
- Same size as before, same speed (measured), and every vanilla fighter gets exactly the same name as before.
- Tested in the emulator (strict mode, no bad memory reads): Records shows "Sora", the Friend Card Settings shows
  "Sora" as the ghost character, the Jukebox shows "Sora : vs Feral Chaos", Original Quest and Quick Battle show
  "Sora", and Cloud / Gabranth / Garland etc. are unchanged on the same screens.

## 2. Words (old = R4 transitional `spot33_ownername.py`, new = generic)

**C1 name_index_eboot, EBOOT FUN_088D6254 (leaf, 11 words, 0x088D6254..0x088D6280).** Old (R4): the vanilla bound plus an owner-33 test that returns
63 (11 words). Vanilla: owners outside 0..34 → 0, then a word load from 0x089CC020[owner] (11 words).
New (= the 10 words of the P2.3 note + a nop):
```
0x088D6254 2c850023  sltiu a1,a0,35        ; owner < 0 or >= 35 -> owner 0 (vanilla: the same bound, 2 tests)
0x088D6258 0005200a  movz  a0,zero,a1
0x088D625C 00042880  sll   a1,a0,2
0x088D6260 3c02089d  lui   v0,0x89d
0x088D6264 00a22821  addu  a1,a1,v0
0x088D6268 8ca2c020  lw    v0,-0x3fe0(a1)  ; vanilla table 0x089CC020[owner]
0x088D626C 94a5f350  lhu   a1,-0xcb0(a1)   ; scenario_names 0x089CF350[owner].name (rowgen D1 row)
0x088D6270 2c840021  sltiu a0,a0,33
0x088D6274 03e00008  jr    ra
0x088D6278 00a4100a  movz  v0,a1,a0        ; owner 33..34 -> the row
0x088D627C 00000000  nop                   ; was R4's dead load of Sora's 63
```
Owners 0..32 → vanilla table; 33..34 → the D1 row; anything else → table[0] = −1 (vanilla). Clobbers a0, a1, v0
(as vanilla). 9 of 11 words differ from R4 (0x088D6254/58 are the same).

**C2 network_name_hook, menu FUN_08A1D7F8 (non-leaf, 17 words, 0x08A1D7F8..0x08A1D83C).** Old (R4): the vanilla
halfword read of 0x08A23ACC[owner−1] with an owner-33 test that gives 63 (17 words). Vanilla: the same read after
sign-extending the owner. New (the first 9 words; ours):
```
0x08A1D7F8 27bdfff0  addiu sp,sp,-16
0x08A1D7FC 00052c00  sll   a1,a1,16
0x08A1D800 afbf0000  sw    ra,0(sp)
0x08A1D804 afa40004  sw    a0,4(sp)        ; ctx, passed on to FUN_08A1D460
0x08A1D808 0e235895  jal   0x088D6254      ; name = C1((s16) owner)
0x08A1D80C 00052403  sra   a0,a1,16
0x08A1D810 8fa40004  lw    a0,4(sp)
0x08A1D814 24470001  addiu a3,v0,1
0x08A1D818 0047380b  movn  a3,v0,a3        ; -1 (owner 0 / out of range) -> 0 = vanilla owner-0 value (0x08A23ACA)
```
0x08A1D81C..0x08A1D838 (8 words): the game's own words for the remaining constant arguments, the call to
FUN_08A1D460 and the epilogue, moved up 3 words; from the call on they are unchanged.
Same 16-byte frame (vanilla used only 0(sp)); same arguments to FUN_08A1D460 for owners 0..33; v0 of the callee
is returned as before. The owner-0 guard stays (P2.3 Q4 not answered at runtime: no owner-0 call was seen; the
guard costs 2 words and keeps vanilla's "0" there). Owners outside 0..34: vanilla read garbage (e.g. 168, 97, 51),
now 0. 11 of 17 words differ from R4. The menu table 0x08A23ACC is no longer read by anything.

**Owner bounds in the new words (for the owner_scan allow-list, PHASE2-START decision 9):**
- EBOOT 0x088D6254 `2c850023 sltiu a1,a0,35` — the range bound (vanilla had a signed bound 35; owner_scan calls 0x23 "bound 35").
- EBOOT 0x088D6270 `2c840021 sltiu a0,a0,33` — generic "owner ≥ 33 reads the scenario_names row" (owner_scan: 0x21 "owner==33").
No other owner or package immediate: the R4 constants 63 (0x088D627C, 0x08A1D810) and both owner-33 compares
(0x088D625C, 0x08A1D80C) are gone.

## 6. Lessons (also notes/dlc.md §F 13)
- One owner → name function + one installer row covers Records, Jukebox voices, Friend Card / ghost names. The
  installer must write the D1 scenario_names row for every package owner; a missing row shows "Warrior of Light".
- PPSSPP debugger: a breakpoint added with `enabled: false, log: true` still **stops** the CPU in this build; a
  key pressed while the CPU is stopped can stay "held" (menus stop reacting): send `input.buttons.send` with every
  button false. In strict mode, hold a button ≈0.3 s, one press per call, and check with a screenshot (longer holds
  auto-repeat, quick sequences get dropped or queued). The debugger socket refuses new connections for a few seconds
  while a scene loads (retry).
